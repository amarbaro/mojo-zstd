# Design

- **Native, no C.** `src/` has no `OwnedDLHandle`, `external_call` or `dlopen` (`grep -rE "DLHandle|external_call|dlopen" src` is empty). Both formats are Mojo ports of the reference algorithms, so the package builds with `mojo precompile` alone, on any host Mojo runs on, and does not depend on the host's library versions. The price is the code: 4.0k lines instead of 230, and an encoder that is 1.3 to 3x slower than libzstd on fast levels.
- **Layout.** `src/lz4/`: `xxh32.mojo`, `block.mojo` (block decoder and fast encoder), `codec.mojo` (frames). `src/zstd/`: `xxh64`, `fse` (backward bit reader, normalized counts, tables), `huf` (Huffman tables and streams), `block` (literals, sequence tables, sequences), `decode` (frame push parser), `entropy` (FSE and Huffman encoders), `enc` (literals and sequences sections, table choice and reuse, block assembly), `finder` (fast, double-fast, hash-chain finders), `opt` (binary tree, optimal parser, lazy parsers), `split` (block pre-split), `compress` (level table, window, frame, block loop, streaming), `codec` (public API).
- **Memory.** One-shot calls size the output from the data they produce and double on demand. `ZstdReader` and `ZstdWriter` hold a window (up to 128 MiB for the largest windows a frame may declare), a 256 KiB input buffer and 128 KiB blocks: 128 MiB streamed peaks at 14.2 MB, 1 MiB at 13.5 MB. Table indices stay in 32 bits: the encoder subtracts a multiple of the chain size from every entry before they pass 2^31, so streams may exceed 4 GiB. `compress()` refuses inputs of 2 GiB or more.
- **Untrusted input.** Errors raise; the gate feeds 10851 corrupt inputs, 12679 bit-flipped reference frames and (outside the gate, `tools/oracle.py vec`) 1.77 million single-bit flips. A header that claims a huge size cannot force an allocation: buffers grow with the bytes actually decoded.

## lz4

- **Decode** follows `LZ4_decompress_safe`: same end-of-block rules (last 5 bytes literals, last match 12 bytes before the end), same offset checks, so corrupt input gets the verdict liblz4 gives. Offset 0 is accepted by liblz4 and copies uninitialised memory; here it copies zeros. Linked blocks see the frame so far, independent blocks only their own. Skippable frames are skipped.
- **Encode** is `LZ4F_compressFrame` at level 0 (liblz4 1.9.4, the version python-lz4 bundles) and its output is byte for byte python-lz4's at three settings (the API's, python's defaults, independent 64 KiB blocks), on 2006 sources and on the 32 MiB corpus. A frame of one block is independent (hash4 over 13 bits below 64 KiB, hash5 over 12 bits above); linked frames use one byte-indexed table over the whole input; a block that does not fit in `size - 1` bytes is stored raw, with lz4.c's conservative output checks so near-misses match.
- Not covered: block checksums on write, levels above 0, dictionaries, the legacy frame format.

## zstd decode

- A push parser (`Zdec.parse`): it takes the bytes available, decodes every complete unit (frame header, block, checksum) and returns what it consumed, so one engine serves a whole buffer (`decompress`, history kept whole) and a file read in chunks (`ZstdReader`, history slid to one window).
- It accepts and rejects what libzstd 1.5.7 does, quirks included, because the gate compares verdicts and bytes with it on corrupt input: libzstd decodes a frame of known size up to 64 KiB in one pass (no window limit, no limit on raw and RLE blocks, an empty compressed block is an error, raw literals read in place may let a block run 32 bytes past the block limit); its streaming path skips the content-size check when the last block is empty; its fast four-stream Huffman loop checks no end marker and reads below a stream's start from the bytes before it; a frame must declare a window of at most 2^27. A dictionary id in a frame is an error (no dictionaries).
- Known difference: a frame whose declared window is smaller than the offsets it uses. libzstd's streaming path reads stale bytes from its ring buffer; `ZstdReader` raises. `decompress` of the same frame agrees with libzstd.

## zstd encode

- Levels -131072..22, parameters from libzstd's table by source size tier (above 256 KiB, up to 256, 128, 16 KiB), adjusted to the size. fast (1, 2, negative): the four-position pipeline; dfast (3, 4); greedy, lazy, lazy2 (5 to 12): hash chains; btlazy2 (13 to 15): lazy2 over the binary tree; btopt, btultra, btultra2 (16 to 22): tree plus the optimal parser (statistics-priced dynamic program, and for btultra2 a first pass that only learns the statistics). Blocks are 128 KiB, cut early where 8 KiB fingerprints change (`split.mojo`).
- Entropy: Huffman literals (one or four streams, weights as FSE or 4-bit, table repeat), sequences with predefined, RLE, new or repeated FSE tables by estimated cost, raw and RLE block fallback with libzstd's rules. Repeat offsets are derived from the actual offsets when a sequence is stored.
- Output is valid zstd, not libzstd's bytes: the gate decodes it with Python and holds it to 5% of libzstd's size at the same level (`docs/perf.md` has the table). Differences from libzstd: hash chains where libzstd 1.5.7 uses a row matcher at levels 5 to 12, the btlazy2 finder takes matches of 4 bytes where libzstd's best-match search needs 9, negative levels still Huffman-code literals (smaller output, slower), no long-distance matching, no dictionaries, no multithreading.
- Streaming (`ZstdWriter`): content size unknown, window from the table (512 KiB at level 1 to 128 MiB at level 22), input copied into a window buffer (history plus two blocks), blocks written through a 128 KiB buffer.

## Gate

`tools/oracle.py` (Python `zstandard`, `lz4`) is a subprocess in the gate, never imported by the library. It is bounded (3 GiB address space, 64 frames and 256 MiB output per input). `scripts/check.sh` runs: 2000 seeded cases and their corrupt variants (verdict and bytes), the zstd repo's golden files and decodecorpus frames with every single-bit flip of the small ones, lz4 byte identity, 20+ zstd levels, negative controls (planted bugs in the harness, a decoder and an encoder with one FSE state off), bounded streaming memory, the API and the README example. A missing `libzstd.so.1` on the machine only affects the oracle (it judges corrupt frames with the system library).
- **Not covered.** Dictionaries, multithreading, long-distance matching, the lz4 block format, lz4 levels, windows or macOS.
